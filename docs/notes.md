# 排查记录与已知限制

## 硬件是好的，不是被阉割

最开始怀疑固件删掉了色温功能。验证方法：进系统自带阅读器的 GLOWLIGHT 页面，把 Cool ←→ Warm 滑块拖到最暖，再读底层节点：

```
leda = 255    ledb = 0
```

暖光通道满、冷光通道零，硬件完全正常。所以问题不在硬件，也不在框架，而在**入口**。

## 为什么写设置项没反应

系统里有 `screen_brightness_color` 这个键，直接 `settings put` 改它，屏幕毫无变化。原因是监听不在这个设置键上 —— 自带阅读器直接调用框架里的前光接口，设置项没有人消费。

也就是说，靠改 Settings 数据库去调色温这条路走不通，必须直接写节点，或者走那个私有接口（后者对普通应用不可用）。

## 未注册机器的死循环

自带阅读器的 GLOWLIGHT 页面属于阅读器应用，设备未完成 Barnes & Noble 注册时进不去。而国内网络环境下注册本身就不顺畅。于是变成：硬件能调 → 唯一官方入口进不去 → 设置项不响应 → 暖光白给。

绕开注册之后（用第三方桌面），这个入口依然不可用，所以才需要这套脚本。

## 其它实测结论

- `hw.CTM.dev` 在 GL4 上是空值。有工具拿这个属性判断「色温是否可用」，在 Nook 上会误判为不可用。
- `ro.hw.frontlight=yes`、`ro.hw.frontlight_table=TABLE0` 存在，但不能作为功能可用的依据。
- 亮度可以用标准 `settings put system screen_brightness` 控制，实测 30 / 60 / 100 都能直接驱动主通道，与色温通道无关。
- GlowLight 4e 与 4 代用同一 SoC，backlight 节点命名相同，实测可写；但 4e 是 764×1024 低分屏，显示效果不同，别混为一谈。

## 适用范围

- 需要 root。未 root 设备无法写 `/sys/class/backlight` 下的节点。
- 只在 Android 8.1 的 GL4 / 4e 上验证过。其他 NTX 方案机型理论上可用（脚本会探测节点），但没有实测，请自行核对。
- 直接写节点是临时生效，重启后会被框架恢复。想要持久化需要自己加开机执行逻辑，本仓库不包含这部分。
- 本仓库不提供任何 APK，也不提供修改版系统镜像。

## 为什么不做成系统应用

原版思路是把工具作为 `android.uid.system` 的系统应用放进 `/system/app/`，但那需要平台签名，而设备上没有平台私钥；用到的设备电源权限是 `signature` 级，priv-app 白名单也绕不过。走 root 脚本是最省事、也不需要改动系统分区的做法。
